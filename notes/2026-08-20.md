## 오늘의 개념: LLM 서비스 배포란 무엇인가
'LLM'은 사람처럼 글을 이해하고 대답을 만들어내는 AI 프로그램을 말하는데, 이걸 마치 '아주 똑똑하지만 혼자서는 밖에 나갈 수 없는 상담사'라고 생각하면 됩니다. '배포'란 이 상담사를 사람들이 실제로 만나서 질문할 수 있도록 상담실을 열고 문을 여는 과정을 뜻합니다. 구체적으로는 컴퓨터(주로 강력한 서버)에 이 AI 프로그램을 설치하고, 사람들이 인터넷을 통해 질문을 보내면 그 질문이 AI에게 전달되고 답변이 다시 사람에게 돌아오도록 통로(이를 'API'라고 부르는데, 쉽게 말해 질문과 답을 주고받는 우체통 같은 것)를 만들어주는 일입니다. 예를 들어 여러분이 챗봇 앱에서 질문을 입력하면, 그 질문은 인터넷을 타고 서버에 있는 AI에게 전달되고, AI가 생각한 답이 다시 앱 화면에 나타나는 것이 바로 '배포된 LLM 서비스'가 작동하는 방식입니다. 이때 사람이 한꺼번에 몰려도 답변이 느려지지 않도록 서버를 여러 대 준비하거나, 비용을 아끼기 위해 AI 모델을 가볍게 만드는 등의 추가 작업도 배포 과정에 포함됩니다.

## 오늘의 용어: LLM 서빙(LLM Serving)
LLM 서빙이란 미리 만들어 놓은 똑똑한 AI 모델(LLM, 즉 사람처럼 글을 이해하고 대답하는 프로그램)을 사람들이 실제로 인터넷이나 앱을 통해 사용할 수 있도록 준비하고 운영하는 과정을 말합니다. 비유하자면, 요리사가 아무리 맛있는 요리(=AI 모델)를 만들어도 손님이 주문하고 받아먹을 수 있는 '식당'이 있어야 하는 것처럼, LLM 서빙은 이 AI 모델을 손님(사용자)이 질문을 보내면 답을 받아볼 수 있게 해주는 '식당 운영' 같은 역할을 합니다. 이 과정에는 여러 사람이 동시에 질문해도 빠르게 답해줄 수 있도록 컴퓨터 자원을 잘 나누어주는 기술적인 관리도 포함됩니다.

## 예제 코드
```python
# FastAPI는 "웹으로 요청을 받고 응답을 주는 접수창구"를 쉽게 만들어주는 도구입니다
from fastapi import FastAPI
# pydantic은 "손님이 보낸 주문서(요청)가 형식에 맞는지 확인해주는 도우미"입니다
from pydantic import BaseModel

# app은 우리가 열 '가게(서비스)' 그 자체를 의미합니다
app = FastAPI()

# 손님이 보낼 주문서의 모양을 정의합니다 (여기서는 "질문" 하나만 받음)
class Question(BaseModel):
    text: str

# "/ask"라는 창구로 손님이 주문서를 보내면 이 함수가 실행됩니다
@app.post("/ask")
def answer(question: Question):
    # 진짜 AI 모델 대신, 받은 질문을 그대로 이용해 가짜 대답을 만듭니다
    fake_answer = f"'{question.text}'에 대한 답변입니다 (예시)"
    # 손님에게 결과를 돌려줍니다 (식당에서 요리를 내주는 것과 같음)
    return {"answer": fake_answer}

# 아래 명령어를 터미널에 입력하면 이 가게(서비스)가 실제로 문을 엽니다:
# uvicorn 파일이름:app --reload

```
'배포'라는 말은 어렵게 들리지만, 쉽게 말하면 "내 컴퓨터에서만 쓰던 프로그램을 다른 사람도 인터넷으로 접속해서 쓸 수 있게 문을 열어주는 것"입니다. 마치 집에서만 만들던 요리를 식당을 열어서 손님들이 주문할 수 있게 하는 것과 비슷합니다. 이 예제는 FastAPI라는 도구(주문을 받는 '식당 접수창구' 역할)를 이용해서, 사람이 질문(텍스트)을 보내면 AI(여기서는 아주 간단히 흉내만 낸 가짜 AI)가 대답을 돌려주는 웹 서비스를 만드는 가장 기본적인 형태를 보여줍니다.

## 실무 팁
'LLM 서비스 배포'란 쉽게 말하면, 여러분이 만든 AI 챗봇을 내 컴퓨터 안에서만 쓰는 게 아니라 인터넷을 통해 다른 사람들도 쓸 수 있게 '가게 문을 여는 것'과 같아요. 요리를 아무리 잘해도 손님이 들어올 수 있는 가게 문이 없으면 소용없듯이, AI 모델도 사람들이 접속할 수 있는 '문(=API 서버)'을 만들어줘야 서비스가 됩니다.

바로 적용 가능한 구체적 팁: 처음 배포할 때는 절대 처음부터 서버를 직접 세팅하려 하지 말고, 'FastAPI(파이썬으로 웹 서버를 쉽게 만드는 도구) + Ollama(내 컴퓨터에서 LLM을 돌려주는 무료 프로그램)' 조합으로 로컬에서 먼저 테스트해보세요. 순서는 이렇습니다:
1) Ollama 설치 후 터미널에 `ollama run llama3` 입력 (마치 스마트폰에 앱 설치하듯 AI 모델을 내 컴퓨터에 설치하는 것)
2) 파이썬으로 FastAPI 서버를 만들어서, 사용자가 질문을 보내면 그 질문을 Ollama에게 전달하고 답변을 받아서 다시 사용자에게 돌려주는 '중간 다리' 코드 10줄 정도만 작성
3) `uvicorn main:app --reload` 명령어로 서버를 켜면, 웹브라우저에서 `localhost:8000`으로 접속해 내 AI 서비스를 테스트할 수 있습니다.

이렇게 로컬에서 완벽히 작동하는 걸 확인한 후에 Render나 Railway 같은 무료 클라우드 서비스에 그대로 업로드하면, 클릭 몇 번으로 실제 인터넷 주소를 가진 서비스가 됩니다. 처음부터 AWS 같은 복잡한 서버를 배우려 하면 좌절하기 쉬우니, '로컬 테스트 → 간단한 무료 클라우드'라는 순서를 꼭 지키세요.</tip>

## 오늘의 퀴즈
Q. LLM(거대 언어 모델, 예를 들면 챗봇처럼 사람과 대화하는 AI 프로그램) 서비스를 '배포'한다는 것은 정확히 무슨 뜻일까요? 이걸 '요리사가 새로운 요리를 개발한 것'과 '그 요리를 손님에게 파는 것'에 비유해서 설명해보세요.
A. LLM을 배포한다는 것은, 연구실에서 학습시켜 완성한 AI 모델을 실제로 사람들이 사용할 수 있도록 서버(컴퓨터)에 설치하고, 앱이나 웹사이트를 통해 누구나 접속해서 쓸 수 있게 만드는 과정을 말합니다. 요리에 비유하면, '모델 학습'은 요리사가 주방에서 레시피를 개발하고 연습해서 맛있는 요리를 완성하는 과정이고, '배포'는 그 요리를 실제 식당 메뉴판에 올려서 손님이 주문하면 바로 만들어 내올 수 있도록 준비하는 것입니다. 즉 아무리 요리(모델)가 훌륭해도 식당(서비스)에 올리지 않으면 손님(사용자)이 먹을 수 없듯이, 배포는 AI 모델을 실제로 사람들이 사용할 수 있게 세상에 내놓는 마지막 단계입니다.
